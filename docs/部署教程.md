# 部署教程

本平台支持两种部署形态：

- **方案 A（推荐，大创答辩/本地演示）**：单服务部署——后端 Express 同时托管前端 `client/dist` 与 API，只需一个进程。
- **方案 B（公网展示）**：前端静态托管到 GitHub Pages，后端单独部署到支持 Node.js 的云服务，通过 `VITE_API_BASE` 跨域调用。

两种方案共用同一套代码与数据库。

---

## 一、环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | **>= 22.5**（使用内置 `node:sqlite`，无编译依赖） |
| npm | 随 Node 安装即可 |
| 操作系统 | Windows / macOS / Linux |
| 磁盘 | 需可写目录保存 `server/data`（数据库）与 `server/uploads`（附件） |

> 数据库为 SQLite 单文件，**不需要安装 MySQL/PostgreSQL**。首次启动会自动建表并写入演示数据。

---

## 二、本地演示（方案 A）

### 1. 安装依赖

```bash
npm install
```

### 2. 构建前端并初始化数据

```bash
npm run build
npm run seed
```

`npm run seed` 为幂等操作：已存在的模板与账号不会重复创建。若需重置演示数据，先删除 `server/data` 与 `server/uploads`，再执行 `npm run seed`。

### 3. 启动

```bash
npm start
```

访问 <http://localhost:3001>。后端会自动托管 `client/dist`，并处理前端路由回退，直接访问 `/teacher` 等路径也可正常打开。

### 4. 前后端分离开发（可选）

```bash
npm run dev:server   # 后端：http://localhost:3001
npm run dev:client   # 前端：http://localhost:5173（自动代理 /api 与 /uploads）
```

### 5. 演示账号

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 教师 | `teacher` | `123456` |
| 学生 | `student` / `s2` / `s3` / `s4` | `123456` |

教师端登录后可在“班级管理”中查看演示班级“八年级(1)班”。

## 三、GitHub Pages（静态前端）+ 独立后端（方案 B）

### 1. 部署后端

任选支持 Node.js 的云平台（Render、Railway、阿里云 ECS、腾讯云轻量应用服务器等），关键配置：

| 配置项 | 值 |
| --- | --- |
| 构建命令 | `npm install && npm run build` |
| 启动命令 | `npm start` |
| Node 版本 | 22.5 及以上 |
| 环境变量 `PORT` | 平台自动注入或自定义（如 `3001`） |
| 环境变量 `CORS_ORIGIN` | 前端站点地址，如 `https://<用户名>.github.io`，多个用英文逗号分隔 |
| 持久化磁盘 | 必须挂载，并把 `server/data` 与 `server/uploads` 放在持久化目录，否则重启会丢失数据与附件 |

若平台无法挂载持久化磁盘，可将 `DATA_DIR` 与 `UPLOAD_DIR` 指向平台提供的持久化路径（见 `server/src/db.js` 顶部常量，按需改为读取环境变量）。

部署完成后访问 `https://<后端域名>/api/health`，应返回：

```json
{ "ok": true, "service": "math-pbl-platform", "time": "..." }
```

### 2. 构建并发布前端

GitHub 仓库需托管**前端静态产物**。在本地执行：

```bash
# Windows PowerShell
$env:VITE_BASE="/<仓库名>/"
$env:VITE_API_BASE="https://<后端域名>"
npm run build
Copy-Item client/dist/index.html client/dist/404.html
```

```bash
# macOS / Linux
VITE_BASE=/<仓库名>/ VITE_API_BASE=https://<后端域名> npm run build
cp client/dist/index.html client/dist/404.html
```

说明：

- `VITE_BASE` 必须是 `/<仓库名>/`（前后都带斜杠）；若使用自定义域名则改为 `/`。
- `VITE_API_BASE` 填**后端根地址，不含 `/api`**。例如后端为 `https://math-pbl.onrender.com`，则填该地址，前端会自动请求 `https://math-pbl.onrender.com/api/...`。
- `404.html` 用于 GitHub Pages 的 SPA 路由回退，否则直接访问 `/teacher` 会 404。

随后把 `client/dist` 的内容推送到 `gh-pages` 分支（或使用 GitHub Actions 自动构建发布）：

```bash
npx gh-pages -d client/dist
```

### 3. 跨域与鉴权注意事项

- 后端 `CORS_ORIGIN` 必须包含前端域名，否则浏览器会拦截请求。
- 前端 Token 存于 `localStorage`，通过 `Authorization: Bearer <token>` 传递；后端不依赖 Cookie，无需额外配置 SameSite。
- 若后端使用 HTTPS，前端也必须使用 HTTPS（GitHub Pages 默认满足）。

---

## 四、关键配置一览

| 位置 | 配置 | 说明 |
| --- | --- | --- |
| 环境变量 `PORT` | 后端端口，默认 `3001` | 单服务部署时同时决定前端访问端口 |
| 环境变量 `CORS_ORIGIN` | 允许的前端来源，逗号分隔；留空允许所有来源 | 生产环境建议显式配置 |
| 构建变量 `VITE_BASE` | 前端静态资源基路径 | GitHub Pages 项目站点为 `/<仓库名>/` |
| 构建变量 `VITE_API_BASE` | 后端根地址（不含 `/api`） | 本地开发留空，走同源或 Vite 代理 |
| `server/data/` | SQLite 数据库、鉴权密钥 | 需持久化，不可提交到 Git |
| `server/uploads/` | 学生/教师上传附件 | 需持久化，不可提交到 Git |

## 五、AI 第二迭代：接入大模型 API

当前版本 AI 为**规则版**：`server/src/aiSkills.js` 依据任务单板块与全文关键词匹配技能，并基于任务单目标、步骤生成启发式问题；`server/src/analysis.js` 生成规则版成果分析。接口契约已按“把当前任务单全文作为上下文”设计。

接入大模型时建议：

1. 新增 `server/src/llm.js`，读取环境变量 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`（兼容 OpenAI 格式的任意服务商）。
2. 上下文组装：`buildTaskText(task)` 已汇总标题、描述、学习目标、实施步骤、评价维度，可直接作为 system/user 内容。
3. 改造 `POST /api/tasks/:id/ai/skills` 与 `POST /api/student/assignments/:id/ai/guide`：先做规则匹配筛选技能，再调用模型生成引导；模型失败时回退到现有规则文案。
4. 成果分析可改为：将评价标准与学生成果拼装为 Prompt，要求模型输出 JSON（建议分、维度得分、亮点、改进建议），解析失败时回退规则版。
5. 大创答辩可使用免费额度（如智谱、通义、DeepSeek、硅基流动等 OpenAI 兼容接口）。

> 提示：不要把 API Key 写入前端或提交到仓库，后端通过环境变量注入。

## 六、常见问题

**Q1：启动报 `ERR_UNKNOWN_BUILTIN_MODULE` 或找不到 `node:sqlite`？**
Node 版本过低，请升级到 22.5 及以上（推荐 22 LTS 最新版）。

**Q2：`npm install` 报 `EPERM` / `'node' is not recognized`？**
Windows 上 Node 未加入 PATH 时，可临时把安装目录加入 PATH 再执行，例如：

```powershell
$env:PATH = "D:\Program Files;" + $env:PATH
& "D:\Program Files\npm.cmd" install
```

本仓库已在 `.npmrc` 中把 npm 缓存改到项目内 `.npm-cache`，避免系统盘权限问题。

**Q3：访问 3001 端口显示空白或接口 404？**
先确认已执行 `npm run build`（生成 `client/dist`），再重启 `npm start`。接口统一以 `/api` 开头，健康检查为 `/api/health`。

**Q4：上传文件后图片打不开？**
附件通过 `/uploads` 静态托管；跨域部署时图片地址会自动使用 `VITE_API_BASE` 拼接，请确认后端域名可公网访问且未被防盗链拦截。

**Q5：如何清空演示数据？**
停止服务，删除 `server/data` 与 `server/uploads`，重新执行 `npm run seed` 与 `npm start`。

**Q6：原始模板会被教师改坏吗？**
不会。模板无写接口，复制操作是深拷贝生成新的 `tasks` 记录，二者数据独立。
